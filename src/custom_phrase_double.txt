# 你开启了完全访问权限，所以这个文件就是 iOS「文本替换」的替代品。
#
# ── 使用前必读：会「抢码」────────────────────────────────────
#
# 这是自定义短语唯一的坑，务必理解：
#
#   任何 2 个字母的组合在双拼里都是合法音节（26 个字母全都是韵母键），
#   所以**你写的短编码几乎一定会和某个正常拼音撞车**。撞车时
#   自定义短语赢 —— 你打那个码就永远出不来汉字了。
#
#   举例：如果写 `电话<Tab>dh`，那么你以后想打「当」时（dang 的双拼
#   编码正好也是 dh），第一个候选永远是"电话"而不是"当"。
#
#   所以原则是：**编码要选你绝不会用来打汉字的字母组合**。
#   5 个字母以上的长编码通常安全，因为它们切不出合法的双拼音节。
#
# ── 怎么生成双拼编码 ────────────────────────────────────────
#
#   若想让编码对应词组的读音，用 tools/ConvertTo-Mspy.ps1：
#       .\ConvertTo-Mspy.ps1 -Pinyin "you xiang"      # -> ybxd
#   它严格复现官方 schema 的映射规则，配 104 条自测用例保证正确。
#
#   编码也可以随便起，不限拼音 —— 但注意上面的抢码问题。
#
# ── 关于「完整编码无法自造词」───────────────────────────────
#
#   上游的提醒：某个词一旦用**完整的**拼音编码固定下来，
#   它就不能再参与造句，自造词也记不住了。
#   所以推荐只固定**非完整拼音**的短编码，或英文单词。
#
#   如果你只是想让某个拼音的首选词固定（比如让「的」永远第一），
#   别写这里，用方案里的 pin_cand_filter 更合适。
#
# ── 本文件默认内容 ──────────────────────────────────────────
#
#   下面只放了一组英文/编程单词，作用是防止纠错（corrector.lua）
#   把英文错认成拼音。例如 Amazon 会被纠成「a ma zong 阿妈粽」，
#   期望的 Amazon 就掉到第二个去了。
#   这些编码够长、切不出合法双拼音节，所以不会抢中文的码。
#
#   不需要的整行删掉即可。
#
